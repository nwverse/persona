# PersonaCore for iOS

The Apple binding of the shared Rust continuity core (#6871, #6793). The iOS app and `PersonaTests` link it; watch,
widgets, Vision, Persona Link and the frozen Mac app do not. It does not replace the production `ChatStore` in phase 1
and has no user-facing text or screen changes.

## Build and verify

```sh
native/app-core/scripts/build-apple.sh
xcrun swift test --package-path apple/Packages/PersonaCore -Xswiftc -warnings-as-errors
```

The builder uses the workspace's pinned Rust toolchain and creates `build/PersonaCoreC.xcframework` with iOS device,
the Mac's iOS-simulator architecture and the macOS host slice. The package's `build/`, `.build/` and Cargo target are
ignored: no XCFramework, static library or dynamic library belongs in a commit. The input hash covers the source files,
toolchain and builder, not the path alone. Run the builder before XcodeGen/Xcode package resolution on a clean checkout.

`Sources/PersonaCoreWire` and `Sources/Serde` are generated by `cargo run -p persona-core-typegen`; do not edit them
manually. `cargo run -p persona-core-typegen -- --check` regenerates both Swift and Kotlin in scratch directories and
byte-compares the committed trees. `PersonaCore` and its tests use Swift 6, nonisolated defaults, strict concurrency and
warnings as errors. The mutable serializer/deserializer classes are not marked Sendable.

The real-C replay is `PersonaCoreContinuityTests` on macOS and in the iOS `PersonaTests` target. It reads every JSON
case under `spec/fixtures/continuity`, dispatches encoded actions, drains patches, applies Insert/Update/Remove, and
compares complete items, ids, continuity fields and effects. `NativeChatStoreContinuityReplay` runs the same JSON
against the unmodified native iOS `ChatStore`. A separate AppModel test proves the native immediate-fill scheduling.

Only `dispatch` is suitable for the UI thread. `drain`, `flush`, creation and `close` stay off the main actor and off
the launch path. Host callbacks run on the Rust worker thread and must not synchronously flush or free that same core;
the C header specifies the ownership and borrowed-buffer contract. The callback box is retained once and released once.
Errors from an effect callback are reported by the next test-only `flush` rather than silently discarded.

The package and fixture replay are not proof of physical-device performance, download-size, launch or memory budgets.
Those remain unmeasured until a named device/simulator, optimized build and workload are reported.
