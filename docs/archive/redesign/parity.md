# Feature parity matrix (existing iOS features + redesign additions)

> Draft v1 (2026-10-30), part of the [redesign plan](README.md). Sections 1–24 list all existing iOS features (213 items, checked individually against Swift source),
> with Android equivalents, complexity and priority; section 25 covers redesign additions for both platforms; section 26 covers iOS features added after the research baseline (77999ab) that Android must match. Original notes: [research/persona-features.md](research/persona-features.md).
>
> **Usage**: once work starts, add **iOS level / Android level** columns to each table, using
> Implemented → Unit tests passed → Mock screenshots passed (light/dark × text size) → Test hub passed → Physical device passed ([README.md](README.md), section 9).
> Currently all 213 iOS items are **Shipped**, and all Android items **Not started**.
> Priority: P0 = required for Android v1; P1 = first batch afterwards; P2 = can wait; ✕ = omit or change form (reasons in [android.md](android.md), section 6).

## 0. Definitions

- **Code size**: 189 files under `ios/`, about 41,800 Swift lines (37,600 excluding tests). Targets: `Persona` (App), `Shared` (App / watch / extensions), `PersonaWatch` (watchOS), `PersonaWidgets` (Live Activity Widget extension), `LiveActivity` (App Intent for Live Activity buttons), unit + UI tests. iOS 26 / watchOS 26, Swift 6 (default MainActor), only third-party dependency MarkdownUI.
- **Server contract**: phone connects only to hub (REST `/api/v1/...` + one WebSocket). Android generally reuses the same API; required server changes are marked **Hub change required**. Sections 1–24 assumed Google services; Android approaches mentioning FCM or Google sign-in are superseded by [README.md](README.md) D8 and sections 25/26 (without Google services: resident connection only, no Google-account sign-in on Android).
- **Complexity** (estimated for someone familiar with Compose): S ≤ 2 person-days; M 3–7 person-days; L ≥ 1.5 person-weeks.
- **Priority**: P0 = required for Android v1; P1 = first batch after v1; P2 = can wait; ✕ = recommend omitting or changing form.
- **Columns**: **iOS-specific capability** names platform dependencies; **Android approach** names Compose / OS APIs, or alternatives when no equivalent exists.
